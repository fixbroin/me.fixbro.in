Next.js on-Demand Home Services Booking System with MySQL & Firebase Auth

Latest Version v1.0.0
Framework & Stack Next.js (App Router), Tailwind CSS, MySQL, Firebase
Author fixbro

1. Introduction

WeCanFix is a premium, mobile-first responsive script designed for service-based agencies, booking centers, or individual handyman businesses. Developed using Next.js App Router and optimized for Hostinger (MySQL Databases & VPS deployment), it provides a seamless booking experience for customers and a complete control panel for administrators.

Key Features:

  • Interactive Landing Page: Slideshows, testimonials, and category grids.
  • Dynamic Category & Services Page: Hierarchical classification of subcategories and listings.
  • Seamless Cart Flow: Instant price calculations, platforms fees, and custom visiting fees.
  • Autopicked Booking Slots: Custom calendar date & time selection.
  • GPS Address Detection: Integrated map search or HTML5 geolocation auto-detect.
  • Multi-Currency Settings: Select any country's currency in the admin settings; the application automatically updates symbols, codes, and correct mathematical decimal units.
  • Razorpay Integration: Seamless client-side checkout and secure server-side signature verification.
  • SEO Generator Module: Bulk landing page generator for dynamic area-based service pages.
  • REST API Backend Architecture: Next.js Route Handlers function as standard REST API endpoints (located in src/app/api/*). This allows developers to easily extend the codebase, build and connect mobile apps (e.g. Flutter or React Native), or integrate with third-party software.
  • Database & Images Management Tools: One-click download of database snapshots (.json) and uploaded media zip archives (.zip) directly through the admin interface, with full one-click restorations and Next.js fetch-cache cleaners.

3. Local Installation & Development Flow

Follow these structured steps to set up and run the application in your local development environment:

  1. Extract and Open:

    Unzip the downloaded CodeCanyon package and open the folder in your code editor (recommended: Visual Studio Code).

  2. Ensure Local Database is Running (e.g., XAMPP):

    You must have a MySQL server running locally to test database integrations. If using XAMPP Control Panel, ensure the MySQL module is started and running on port 3306. Create a blank database schema (e.g. wecanfix_db) using phpMyAdmin or any MySQL tool.

  3. Configure Environment File:

    Copy the file named .env.example, rename it to .env in the project root directory, and fill in your database and third-party configuration keys:

    cp .env.example .env
  4. Configure Administrator Email:

    Open the file src/contexts/AuthContext.tsx in your editor. Find line 36 where the admin email is defined:

    export const ADMIN_EMAIL = "admin@yourdomain.com";

    Change "admin@yourdomain.com" to your preferred administrator email. When you register/sign up on the website's frontend with this exact email address, the system will automatically authorize and create your profile with full Super Admin privileges.

  5. Install Dependencies:

    Open the VS Code integrated terminal and run the install command to configure dependencies:

    npm install
  6. Update Branding and Domains (Search-and-Replace):

    Use VS Code's global search (Ctrl + Shift + F) to customize hardcoded references:

    • Search for wecanfix and replace it with your custom brand name (e.g. yourbrand).
    • Search for wecanfix.in and replace it with your own website domain name (e.g. yourdomain.com).
  7. Configure PWA Manifests & Brand Logo Images:

    The application runs as a Progressive Web App (PWA). You must customize the manifest files and brand logos inside the public/ folder:

    1. Ensure the metadata parameters (name, short_name, and description) inside public/manifest.json, public/manifest-admin.json, and public/manifest-provider.json reflect your brand. (Performing Step 5 handles most updates, but verify the files).
    2. Navigate to the online favicon utility: Favicon & PWA Icon Generator.
    3. Upload your primary high-resolution business logo. The system automatically creates all favicons and PWA-required icon resolutions.
    4. Download the generated icon zip archive, extract it, and copy/overwrite all files directly into the project's public/ folder (replacing standard favicons, apple-touch-icon.png, and chrome images).
  8. Launch Development Server:

    Run the development server script. On first startup, the database compiler will automatically populate all system tables in your local database:

    npm run dev

    The website will be accessible locally at http://localhost:3006. Open the website, log into the admin dashboard, and verify everything works.

  9. Production Compilation:

    Once you verify that everything is working locally, build the production bundle before deploying to VPS or standalone hosting:

    npm run build

5. MySQL Database Setup

WeCanFix utilizes a modern JSON-document hybrid schema over MySQL. This means you get the reliability of relational databases while preserving document-level query flexibility.

💡 DB Migration Autoloading
You do not need to manually import any database tables or SQL scripts. When the project starts up via npm run dev or npm run build, a script called scripts/db-init.js automatically runs, queries your schema configurations, and constructs any missing tables.

Manual Database Setup Instructions:

  1. Create a schema in your database client (like Hostinger phpMyAdmin or MySQL Workbench): 
    CREATE DATABASE your_database_name CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  2. Update your .env file with the correct MYSQL_HOST, MYSQL_USER, MYSQL_PASSWORD, and MYSQL_DATABASE.
  3. Start the server. The tables (like bookings, webSettings, adminServices, and others) are generated on-the-fly.

6. Firebase Integration Guide

Firebase handles two key areas of the app: **Authentication** (including Phone/OTP sign-in, Email, and Google accounts) and **Media File Upload Storage**.

Step 1: Setup a new Firebase Project

  1. Go to the Firebase Console and click Create Project.
  2. Add a web app to your project under Project Settings to generate the config keys (API key, Auth Domain, Project ID, App ID, etc.).
  3. Copy these values into your client-side environment variables (e.g. NEXT_PUBLIC_FIREBASE_API_KEY).

Step 2: Enable Authentication Methods

In the Firebase Console sidebar, go to Build -> Authentication, enable it, and configure the following sign-in providers:

  • Email/Password: Toggle enabled.
  • Google Account: Toggle enabled.
  • Phone Number (OTP Verification): Toggle enabled. Ensure you whitelist your testing numbers.

Step 3: Setup Google Cloud Storage Bucket

Go to Build -> Storage and click Get Started. Set the rules to allow public read/write or edit access for your media files upload route.

Step 4: Generate Firebase Service Account JSON (Admin SDK)

To securely access user records and write authentication middleware on the server side, you need an Admin SDK credential:

  1. Go to Project Settings (gear icon) -> Service accounts.
  2. Click Generate new private key. This will download a JSON file containing sensitive credentials.
  3. Open the JSON file, copy the entire string, and assign it to FIREBASE_ADMIN_SDK_CONFIG inside your .env file: 
    FIREBASE_ADMIN_SDK_CONFIG='{"type": "service_account", "project_id": "your_project_id", "private_key": "-----BEGIN PRIVATE KEY-----\nyour_private_key_lines_here\n-----END PRIVATE KEY-----\n", ...}'

Step 5: Configure Firebase in Admin Panel (Required for Chats & Notifications)

Real-time chat and Firebase web push notifications require the credentials to be configured inside the Admin Panel settings:

  1. Log into your Admin dashboard and navigate to Marketing IDs in the sidebar.
  2. Select the Firebase tab.
  3. Provide the following configurations:
    • Firebase Public VAPID Key: Paste your Web Push Key (generate this in Firebase Console under Project Settings -> Cloud Messaging -> Web Push certificates).
    • Full Client Config: Enter your Firebase client config parameters (API Key, Auth Domain, Project ID, Storage Bucket, Messaging Sender ID, App ID, Measurement ID).
    • Admin SDK JSON: Paste the full stringified content of the service account private key JSON file generated in Step 4.
  4. Click Save All Marketing Settings. This ensures real-time updates and push messaging work seamlessly across user chat modules.

7. VPS & PM2 Setup & Production Deployment

This section provides comprehensive, step-by-step instructions to configure **MySQL Server**, **Node.js**, **Nginx Reverse Proxy**, **SSL Certificates**, and **PM2 Process Manager** on an Ubuntu/Debian VPS (such as Hostinger VPS, AWS, or DigitalOcean) to host your application under your domain name.

You can also reference the standalone markdown guide in this folder: VPS_SETUP_GUIDE.md.

Step 1: Connect to VPS & Install Dependencies

Connect to your server via SSH as root or a sudo user:

ssh root@your_vps_ip_address

Update system packages and install Node.js 20 LTS, Nginx, Git, Unzip, and build compilers:

sudo apt update && sudo apt upgrade -y
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs nginx git build-essential unzip

Install **PM2 globally** to manage your server background processes:

sudo npm install -g pm2

Step 2: Install & Secure MySQL Server

Install and enable the MySQL database service:

sudo apt install -y mysql-server
sudo systemctl start mysql
sudo systemctl enable mysql

Run the security initialization utility (optional but recommended):

sudo mysql_secure_installation

Step 3: Create MySQL Database & User

Log into the MySQL command line interface:

sudo mysql

Run these SQL statements to configure your clean database schema and user credentials:

CREATE DATABASE your_database_name CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'your_database_user'@'localhost' IDENTIFIED BY 'SuperStrongPassword123!';
GRANT ALL PRIVILEGES ON your_database_name.* TO 'your_database_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;

Step 4: Upload and Build Next.js Application

Deploy the application files to the /var/www/ directory on your VPS using either Option A or Option B:

  • Option A (Git): Push your customized code to a private Git repository and clone it: 
    cd /var/www
git clone <YOUR_GIT_REPOSITORY_URL> your-app-directory
cd your-app-directory
  • Option B (SFTP/Zip): Zip the project folder (excluding node_modules and .next), upload it via FileZilla/Cyberduck to /var/www/, and extract it: 
    cd /var/www
unzip your-package.zip -d your-app-directory
cd your-app-directory

Create a production environment configuration file .env:

nano .env

Paste your environment keys (replicating your local configurations but specifying production values), save, and exit. Then install dependencies and compile the production build:

npm install
npm run build

Step 5: Start Application with PM2

Start the production Next.js backend standalone server using PM2 to keep it running 24/7:

pm2 start .next/standalone/server.js --name "your-app-name"
pm2 save
pm2 startup

(Copy and run the system command printed by pm2 startup to enable auto-boot on VPS restarts).

Step 6: Configure Nginx Reverse Proxy & SSL

Create a new site configuration file under Nginx:

sudo nano /etc/nginx/sites-available/your-app-name

Paste this initial HTTP block to forward domain requests to Next.js running on port 3006:

server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    client_max_body_size 500M;

    location / {
        proxy_pass http://127.0.0.1:3006;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Save and close the file. Then, enable the config and restart Nginx:

sudo ln -s /etc/nginx/sites-available/your-app-name /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

Request and automatically configure a Let's Encrypt SSL certificate for HTTPS:

sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com

(Follow the prompts and select option to redirect HTTP traffic to HTTPS).

Hardening Caches & Anti-Cloning Security (Highly Recommended)

Once Certbot configures SSL, open the Nginx config file again to append caching headers for static assets and framing protections to prevent cloning and clickjacking attacks:

sudo nano /etc/nginx/sites-available/your-app-name

Replace the configuration with this secure production-grade Nginx structure:

# Redirect HTTP → HTTPS (Automated by Certbot)
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    return 301 https://yourdomain.com$request_uri;
}

# Main HTTPS server
server {
    listen 443 ssl http2;
    server_name yourdomain.com www.yourdomain.com;

    # Allow large database backups and image ZIP uploads up to 500MB
    client_max_body_size 500M;

    ssl_certificate /etc/letsencrypt/live/yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    # Security headers (Prevents clickjacking and site framing/cloning)
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header Content-Security-Policy "frame-ancestors 'self'" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Static files cache (Optimizes browser asset loading speed)
    location ~* \.(jpg|jpeg|png|gif|webp|svg|ico|css|js|woff|woff2|ttf)$ {
        expires 30d;
        access_log off;
        add_header Cache-Control "public, max-age=2592000, immutable";

        proxy_pass http://127.0.0.1:3006;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Next.js static framework assets
    location /_next/static/ {
        expires 365d;
        access_log off;
        add_header Cache-Control "public, immutable";

        proxy_pass http://127.0.0.1:3006;
        proxy_set_header Host $host;
    }

    # Main Next.js App Reverse Proxy with WebSocket support
    location / {
        proxy_pass http://127.0.0.1:3006;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}

Save and restart Nginx once more:

sudo nginx -t && sudo systemctl restart nginx

Step 7: Post-Deployment Verification

Verify that your Node app process and MySQL database are running without issues:

pm2 status
pm2 logs your-app-name
sudo systemctl status mysql

8. Local Standalone Build Deployment (Optional - For Low-RAM VPS)

If your VPS has 1GB of RAM or less, running npm run build on the server may freeze or crash because compiling Next.js requires high memory. You can compile the project on your local machine and upload only the production build files.

Your project includes a custom compiler script (scripts/postbuild.js) that automatically bundles all essential public assets and static files into the .next/standalone/ folder during building.

Step-by-step Local Build Setup:

  1. On your local machine, open the project in VS Code.
  2. Configure your production environment credentials inside your local .env file.
  3. Run the build command locally: 
    npm run build
  4. The postbuild script will automatically package and copy your public/ and .next/static/ folders inside the .next/standalone/ folder.
  5. Compress the contents of the .next/standalone/ folder along with your production .env file into a ZIP archive (e.g. standalone.zip).
  6. Upload standalone.zip using an SFTP client (like FileZilla or Cyberduck) directly to your VPS directory (e.g. /var/www/your-app-directory).
  7. SSH into your VPS, navigate to the folder, and extract the archive: 
    cd /var/www/your-app-directory
unzip standalone.zip
  8. Start your application directly with PM2 (without running npm install or npm run build on the VPS): 
    pm2 start server.js --name "your-app-name"
pm2 save
pm2 startup

9. Remote Database Setup (Optional Shared Hosting DB)

If you prefer to host your Next.js application on a VPS but wish to keep your MySQL database on a separate Shared Hosting server (like Hostinger, cPanel, or hPanel) for extra safety, backups, or database management, you can configure a remote database connection.

Please refer to the detailed guide file: SHARED_HOSTING_DATABASE_SETUP_GUIDE.md inside this Documentation directory.

Summary of Remote Database Setup:

  1. Create a MySQL database and user inside your Shared Hosting dashboard (hPanel/cPanel).
  2. Enable Remote MySQL access for the newly created database, setting IP to % (Any Host) or your VPS IP.
  3. Update your Next.js project .env file with the remote host address (e.g. mysql.yourdomain.com) instead of localhost: 
    MYSQL_HOST=mysql.yourdomain.com
MYSQL_USER=your_database_user
MYSQL_PASSWORD=your_database_password
MYSQL_DATABASE=your_database_name
MYSQL_PORT=3306
  4. Start the server. The tables will initialize automatically on first connect.

10. Cron Jobs Setup

WeCanFix uses automated backend triggers for SEO generation (Google Indexing API) and marketing tasks.

Active Cron Endpoints:

  • Google Indexing Cron: Daily URL compiler. Runs at 1 AM. 
    https://yourdomain.com/api/indexing-cron?secret=your_cron_secret_here
    ⚠️ Google API Library Requirement:
    You must enable the Web Search Indexing API in your Google Cloud Console for the indexing cron to function:
    1. Go to the Google Cloud API Library.
    2. Select your Firebase/Google Cloud project.
    3. Search for "Indexing API" (or "Web Search Indexing API") and click Enable.
    4. Ensure the service account email is authorized as an Owner inside your Google Search Console property settings.
  • Marketing Automation Cron: Handles abandoned carts and booking triggers. Runs every 2 hours. 
    https://yourdomain.com/api/marketing-cron?secret=your_cron_secret_here

Adding Cron Jobs on VPS:

Open crontab: crontab -e. Append these rules to the bottom:

0 1 * * * curl -s "https://yourdomain.com/api/indexing-cron?secret=your_cron_secret_here" >/dev/null 2>&1
0 */2 * * * curl -s "https://yourdomain.com/api/marketing-cron?secret=your_cron_secret_here" >/dev/null 2>&1

11. Payments & Settings Integration

You can configure currencies and payment options directly inside the **App Settings** section of the Admin Panel.

Setting up Currency & Timezone:

  1. Log into your admin dashboard and navigate to App Settings in the sidebar menu.
  2. On the General tab, select your Country Currency.
  3. The system will automatically configure the correct Currency Symbol and standard Decimal Point precision. You can manually adjust them if needed.
  4. Set your business's Application Timezone (e.g. India (IST)) on this same page.
  5. Click Save General Settings at the bottom of the section.

Setting up Razorpay:

  1. Log into your admin dashboard and navigate to App Settings in the sidebar.
  2. Click the Payment tab.
  3. Toggle Enable Online Payments (Razorpay) to ON.
  4. Enter your Razorpay Key ID and Razorpay Key Secret (test keys for testing, live keys for production).
  5. Make sure to toggle Enable "Pay After Service" if you want to support Cash on Delivery (COD).
  6. Click Save Payment Settings. The system automatically syncs these credentials dynamically.

Configuring Provider KYC Documents:

The application has a built-in **Custom Document Maker** inside the Admin Panel. This allows you to request any type of identity verification document from providers during registration (e.g., Driver's License, Passport, National ID, SSN) based on your target country:

  1. Log into your admin dashboard and navigate to Provider Controls in the sidebar menu.
  2. On the Document Types tab, click Add Document Type to create a new requirement.
  3. Specify the label, description, whether it is mandatory, how many images are required (1 or 2), and any character validation rules for the document number.
💡 Enabling Indian KYC (Aadhaar & PAN):
If you want to require Aadhaar and PAN cards with built-in format validations (specifically for India):
  1. Log into your admin dashboard and navigate to Provider Controls in the sidebar.
  2. Select the Registration Settings tab.
  3. Toggle the Default Indian KYC (Aadhaar & PAN) option to ON and click Save Settings.
If you are targeting international markets, you can turn this toggle OFF, and rely purely on the custom documents defined in the Document Types tab.

Setting up Marketing, Analytics & Microsoft Clarity:

  1. Navigate to Marketing IDs in the sidebar menu under Homepage & Marketing.
  2. Google Integrations (Analytics & Tag Manager):
    • Select the Google tab.
    • Fill in your Google Tag Manager ID (e.g. GTM-XXXXXXX), Google Analytics 4 Measurement ID (e.g. G-XXXXXXXXXX), and Google Ads Conversion ID/Label.
  3. Microsoft & Other Platforms:
    • Select the Other Platforms tab.
    • Fill in your Microsoft Clarity Project ID (e.g. your_project_id_here) to enable session recordings and heatmaps, or paste your Pinterest Tag ID / Bing Ads UET Tag ID.
  4. Click Save All Marketing Settings at the bottom of the page to apply.

Database & Images Backups (Highly Recommended):

💾 Backup Before Updates or Migrations

Before running updates, changing backend configurations, or migrating servers, it is highly recommended to download a full snapshot of your website data directly from the Admin Panel.

  1. Log into the admin dashboard and navigate to Database Tools in the sidebar.
  2. Database Snapshot: Under the Database Export & Restore tool, click Download Database Backup (.json). This generates and downloads a structured JSON snapshot containing all system tables and configurations.
  3. Images Archive: Under the Images Backup & Restore tool, click Download Images Backup (.zip). This compiles and downloads all files uploaded inside the /public/uploads/ directory.
  4. Restore Data: To restore matching tables or files from a previous backup, select the downloaded .json or .zip file in the respective Restore slot and click Restore Database or Restore Images Archive.
  5. Cache Purging: Under the Next.js Disk Cache Management widget at the bottom of the page, click the red Clear Next.js Disk Cache button to remove expired pre-rendered pages and free up storage space on your VPS.

12. Remote Media Storage Setup

WeCanFix supports Dual Storage Drivers, allowing you to save VPS disk space and bandwidth by hosting images on a remote shared hosting server instead of your Next.js server.

Overview:

  • Local VPS Storage (local): Stores images directly on your VPS SSD disk (/public/uploads/).
  • Remote Shared Hosting Storage (remote): Uploads images to a Shared Hosting subdomain (e.g., https://media.yourdomain.com) using a secure PHP bridge.

Step 1: Set Up Shared Hosting Subdomain

  1. Log into your Hostinger / Shared Hosting hPanel.
  2. Go to Domains -> Subdomains and create a subdomain: e.g., media.
  3. Ensure SSL (HTTPS) is active for the subdomain.

Step 2: Upload upload.php to Subdomain

  1. Locate the file SHARED_HOSTING_MEDIA_UPLOAD_SCRIPT.php in the Documentation directory.
  2. Rename it to upload.php.
  3. Upload it to the root directory (/public_html/) of your new media subdomain.
  4. Open it in a text editor and configure your custom API secret key: 
    define('SECRET_KEY', 'your_custom_secret_key_here');
define('MEDIA_BASE_URL', 'https://media.yourdomain.com');

Step 3: Configure Admin Settings

  1. Open your Admin Panel and click on Web Settings in the sidebar menu.
  2. Click the Media Storage tab.
  3. Select Remote Shared Hosting Server (it will show as Active when saved).
  4. Fill out the configuration fields:
    • Remote Upload Script URL: https://media.yourdomain.com/upload.php
    • Security Secret Key: your_custom_secret_key_here (must match the key configured inside upload.php)
  5. Click Save Storage Settings at the bottom of the section. The system will now route image upload operations to the subdomain.

Step 4: Whitelist Domains in next.config.ts (Required)

⚠️ Required for Next.js Image Loading

Next.js requires all external image domains/subdomains to be whitelisted for safety and dynamic optimization. If your website domain or remote media subdomain is not listed in your config, images will fail to render with an "Invalid src prop" error.

Before building the app, open next.config.ts in the project root, locate the remotePatterns array, and add your domain rules:

remotePatterns: [
  { protocol: 'https', hostname: 'yourdomain.com' },
  { protocol: 'https', hostname: '*.yourdomain.com' }, // Whitelists your subdomains (e.g. media.yourdomain.com)
  { protocol: 'https', hostname: 'firebasestorage.googleapis.com' },
  // ... keep other default patterns ...
]

After saving, rebuild and restart the app: npm run build and pm2 restart your-app-name.

13. Custom Branding & Global Search-and-Replace

Although most user-facing titles and descriptions are configured dynamically in the Admin Panel settings, some metadata assets, PWA manifest configurations, and automated email/SEO template keywords are hardcoded with the default branding.

To brand the application with your own brand name and website name, follow this simple global search-and-replace method using **VS Code**:

Step 1: Open the Project in VS Code

Unzip your purchased CodeCanyon package, open the project folder in VS Code, and ensure you have completed your .env file configuration.

Step 2: Perform Global Search and Replace

  1. Click the Search icon in the VS Code sidebar (or press Ctrl + Shift + F / Cmd + Shift + F).
  2. In the **Search** field, enter: 
    wecanfix
  3. In the **Replace** field, enter your own desired website/brand name: 
    YourBrandName
  4. We recommend running this twice to match cases properly:
    • Search for capitalized Wecanfix ➔ Replace with capitalized YourBrandName.
    • Search for lowercase wecanfix ➔ Replace with lowercase/capitalized as needed.
  5. This will automatically update occurrences in files such as:
    • PWA Manifests: public/manifest.json, public/manifest-admin.json, and public/manifest-provider.json (changing app names like "Wecanfix Admin" to "YourBrandName Admin").
    • Email Flows & Templates: src/ai/flows/*.ts (changing AI prompt and template references).
    • SEO Metadata: src/app/about-us/page.tsx, src/app/layout.tsx, and other static pages.
  6. Click the **Replace All** button next to the replace field to apply changes globally.

Step 3: Replace Logos & Generate Favicons

Progressive Web Apps (PWA) require specific icon sizes (such as 192x192, 512x512) and browser favicons. You can generate all of these files automatically:

  1. Go to the online generator: Favicon & PWA Icon Generator.
  2. Upload your high-resolution square brand logo.
  3. Download the generated zip archive containing your custom favicons and icons.
  4. Extract the archive and paste the files directly into your project's public/ folder, overwriting the default placeholders (like favicon.ico, apple-touch-icon.png, android-chrome-192x192.png, and pwa-192x192.png).
💡 Rebuild After Branding
Because these configuration files are compiled at build time, you must rebuild the Next.js production build for your custom PWA manifest and static branding changes to take effect: 
npm run build
